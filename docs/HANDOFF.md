# AgentMeter 인수인계 — 같은 디자인·사용성으로 새 앱 만들기

이 문서는 AgentMeter(AI 코딩 에이전트 사용량 위젯)에서 **기능과 상관없이 다시 쓸 수 있는 것**만 모은 문서예요.
디자인 시스템, 창·트레이·단축키·알림·자동 업데이트 같은 데스크톱 앱 뼈대, 개발·배포 방식,
그리고 실제로 겪은 함정을 정리했어요. 새 앱의 기능(사용량 수집, 에이전트 로그 파싱 등)은 다루지 않아요.

> 새 앱을 Claude Code와 같이 만든다면, 이 파일을 새 저장소의 `docs/HANDOFF.md`로 넣고
> 첫 메시지에서 "docs/HANDOFF.md의 디자인 시스템과 구조를 따라서 ○○ 앱을 만들어줘"라고 하면 돼요.
> 원본 코드는 `cheapbutsimilar/agents_usage_monitor`에 있어요. 아래 경로는 모두 그 저장소 기준이에요.

## 1. 제품 원칙 (사용성)

만들면서 사용자 피드백으로 굳어진 원칙이에요. 새 앱에도 그대로 적용하는 걸 권해요.

1. **기본값으로 바로 쓸 수 있어야 해요.** 묻지 않고 켜져야 하는 건 기본값으로 켜요. 설치 직후 화면이 곧 완성된 화면이어야 해요.
   설정 파일에 버전을 두고, 기본값이 바뀌면 마이그레이션으로 기존 사용자에게도 적용해요 (§4.1).
2. **모드를 늘리지 말고 한 화면의 '모양'으로 바꿔요.** 처음엔 "작업표시줄 모드 / 떠 있는 모드"를 따로 만들었는데,
   사용자는 "같은 위젯인데 디자인만 고르는 것"을 원했어요. 기능이 같으면 레이아웃 옵션 하나로 묶어요.
3. **설정은 어디서든 한 번에 닿게 해요.** 더블클릭도 좋지만 톱니바퀴 버튼을 위젯과 대시보드 양쪽에 둬요.
4. **알림은 드물게, 중요할 때만 보내요.** 같은 사건은 한 주기에 한 번만 알리고, 앱을 재시작해도 그 기록이 남아야 해요.
   경계값 근처에서 오르내리는 값은 히스테리시스로 막아요 (§5.6).
5. **숫자는 절대 서로 붙으면 안 돼요.** 표는 고정 열 너비로 만들고, 이름 열이 양보(말줄임)해요.
   공간이 부족하면 나란히 놓인 표를 위아래로 쌓아요 (§3.6).
6. **사용자가 꾸밀 수 있되, 망가뜨릴 수는 없게 해요.** 테마, 색, 투명도, 크기를 바꿀 수 있지만 모두 범위가 정해져 있어요.
   대비가 4.5:1 아래로 떨어지면 경고를 띄워요.
7. **한국 사용자 기준이에요.** 해요체, 짧은 문장, 원화(₩) 표시, 상대 시간("3시간 22분 후") 기본.
8. **모든 창 이동은 자유로워야 해요.** 멀티 모니터, 배율이 다른 모니터, 전체 화면 앱 위에서도 걸리거나 튀면 안 돼요 (§5.3).

## 2. 디자인 시스템

### 2.1 색 토큰 — `ui/shared/tokens.css`

기본 테마(다크) 기준이에요. 실제 값은 테마 엔진(§2.4)이 배경·글자·강조색 세 가지에서 계산해 덮어써요.

| 역할 | 변수 | 값 |
|---|---|---|
| 배경 | `--bg` | `#2B2B2B` |
| 움푹한 면 (타이틀바, 사이드바) | `--bg-sunken` | `#242424` |
| 올라온 면 (카드) | `--bg-raised` | `#333333` |
| 호버 | `--bg-hover` | `#3A3A3A` |
| 입력칸 | `--bg-input` | `#262626` |
| 구분선 / 강한 구분선 | `--line` / `--line-strong` | 흰색 8% / 14% |
| 글자 1·2·3단계 | `--text` / `--text-2` / `--text-3` | `#F3F3F3` / `#B4B4B4` / `#808080` |
| 키 컬러 | `--accent` | `#F05C1A` (hover `#FF6E2E`, press `#D94F12`) |
| 키 컬러 옅은 배경 / 선 | `--accent-soft` / `--accent-line` | 14% / 45% |
| 키 컬러 위 글자 | `--on-accent` | 밝기에 따라 흰색 또는 `#141414` |
| 게이지: 정상 / 경고 / 위험 | `--meter-ok` / `--meter-warn` / `--meter-crit` | 거의 흰색 / 키 컬러 / `#FF453A` |

**색 쓰는 규칙**
- 키 컬러는 "주목해야 할 것"에만 써요: 선택된 탭, 주 버튼, 경고 수준 게이지, 업데이트 배지.
- 정상 상태는 무채색이에요. 게이지도 평소엔 흰 막대이고, 임계치를 넘으면 그때 키 컬러, 더 넘으면 빨강으로 바뀌어요.
- 항목 식별색(에이전트별 색 같은)은 배경 대비를 검증한 몇 개만 고정해서 써요.

### 2.2 타이포그래피

- 글꼴: `Pretendard Variable → Segoe UI Variable → Malgun Gothic → system-ui`. 숫자용은 `JetBrains Mono / Cascadia Mono / Consolas`.
- 숫자는 항상 고정폭 숫자(`font-feature-settings: 'tnum'`, `font-variant-numeric: tabular-nums`)로 써요. 값이 바뀌어도 자리가 흔들리지 않아요.
- 크기: 본문 13px / 보조 12~12.5px / 캡션·표 머리 11px / 페이지 제목 20px / KPI 값은 크게.
- 행간 1.5, 설명문(`small`)은 1.55. 처음엔 빡빡했다가 "답답하다"는 피드백을 받고 넓혔어요.

### 2.4 테마 엔진 — `ui/shared/theme.js`

- 사용자가 고르는 건 **배경·글자·강조색 세 가지**뿐이에요. 나머지 30여 개 변수(움푹한 면, 호버, 선, 2·3단계 글자, 그림자, 툴팁 배경 등)는 이 셋을 섞어서 계산해요.
  그래서 어떤 색을 골라도 화면 구조가 무너지지 않아요.
- 프리셋 6개가 각각 다크·라이트 버전을 가지고 있어요. 모드는 시스템 / 라이트 / 다크이고, 시스템이면 OS 설정 변화를 따라가요(`matchMedia`).
- 글꼴은 정해진 5개 중에서만 고를 수 있어요. 대시보드 배율은 90 / 100 / 110 / 125%예요(`zoom`).
- 위젯 크기(막대 너비, 높이, 카드 너비, 모서리)도 CSS 변수로 넘기고, 설정에서 범위를 제한해요.
- 대비가 4.5:1 아래면 설정 화면에 경고를 띄워요(`AM_THEME.contrast`).
- **새 앱에서는 이 파일을 거의 그대로 가져다 쓰면 돼요.** 프리셋 이름과 키 컬러만 바꾸면 돼요.

### 2.5 컴포넌트 (대시보드 — `ui/dashboard/dashboard.css`, `dashboard.js`)

UI는 프레임워크 없이 문자열 템플릿 함수로 그려요. 페이지 전체를 다시 그리고 스크롤 위치만 유지하는 단순한 방식이에요.

```js
const sw  = (attrs, on) => `<label class="switch"><input type="checkbox" ${attrs} ${on ? 'checked' : ''}/><span></span></label>`;
const row = (label, sub, control) => `<div class="row"><div class="lb">${label}${sub ? `<small>${sub}</small>` : ''}</div>${control}</div>`;
const seg = (name, options, value) => `<div class="seg">${options.map(([v, l]) =>
  `<button data-seg="${name}" data-v="${v}" class="${String(value) === String(v) ? 'active' : ''}">${l}</button>`).join('')}</div>`;
```

| 컴포넌트 | 쓰임 |
|---|---|
| `.titlebar` | 로고 마크(12px 키 컬러 사각형) + 앱 이름 + 버전, 오른쪽에 상태 텍스트·업데이트 배지·톱니·새로고침·최소화·최대화·닫기 |
| `.side` | 왼쪽 내비게이션. 아래쪽(`.side-foot`)에 빠른 전환 컨트롤과 단축키 힌트 |
| `.page-head` | 페이지 제목 + 한 줄 설명 + 오른쪽 액션 |
| `.card` | 모든 묶음의 기본 상자 |
| `.grid2` / `.grid4` | 2열 / 4열 카드 격자 (`minmax(0, 1fr)` — 내용이 길어도 열이 안 넘쳐요) |
| `.kpi` | 라벨(k) / 큰 값(v) / 보조 설명(s) 세 줄 |
| `.rows .row` | 설정 행: 왼쪽 라벨+설명, 오른쪽 컨트롤 |
| `.seg` | 2~4개 중 하나 고르기 (스위치로 표현 안 되는 선택) |
| `.switch` | 켜기/끄기 |
| `.chip` | 여러 개 토글 (색 점 포함) |
| `.inp`, `.inp.num` | 입력칸 |
| `.btn`, `.btn.primary` | 버튼 (주 버튼만 키 컬러) |
| `.status` | 점 + 상태 글자 (작업 중 / 마지막 활동 …) |
| `.tag` | 작은 출처 표시 ("공식 API · 2분 전"), 오래되면 `stale` 클래스 |
| `.meter` | 게이지 막대 + 선택적 페이스 눈금 |
| `.tbl` | 고정 열 표 (§3.6) |
| `.empty` | 빈 상태 안내 문장 |
| `.toast` | 아래쪽 짧은 확인 메시지, 2.4초 |
| `.note`, `.tip-line`, `.warn`, `.err` | 안내 / 팁 / 경고 / 오류 문장 |
| `.mode-tiles`, `.swatches`, `.colorf`, `.rangef` | 모양(테마) 설정 화면 전용 |

**대시보드 페이지 구성**(참고용): 개요 · 분석 · 위젯 표시 · 모양 · 연결(에이전트) · 알림·단축키 · 일반.
"일반"에는 시스템 시작 시 자동 실행, 업데이트(지금 확인 / 자동 업데이트), 통화·환율, 데이터 폴더 열기가 있어요.

### 2.6 위젯 (`ui/shared/widget.css`, `ui/shared/render.js`, `ui/widget/`)

- 같은 렌더러를 위젯 창과 대시보드의 미리보기가 같이 써요. 설정을 바꾸면 미리보기가 즉시 바뀌어요.
- **가로형**(한 줄 스트립, 작업표시줄에 붙일 수 있음)과 **카드형**(떠 있는 카드) 두 가지 레이아웃이 있어요.
- 배경은 `rgba(var(--bg-rgb), var(--op))`예요. 투명도를 사용자가 정할 수 있어요.
- 표시 요소(로고, 이름, 라벨, 막대, %, 리셋, 페이스 눈금, 예측, 비용, CPU/RAM, 설정 버튼)를 각각 켜고 끌 수 있어요.

### 2.7 글쓰기 톤

- 해요체로, 짧게 써요. 예: "지금 속도면 40분 후 소진", "다시 넉넉하게 쓸 수 있어요".
- 설정 설명은 "무엇을 하는지"를 한 줄로 써요. 조건이 있으면 괄호로 덧붙여요: "(한 주기에 한 번)".
- 오류는 원인과 해결을 같이 써요: "로그인 만료 — 원클릭 연결로 다시 로그인하세요".
- 숫자 표기:
  - 큰 수는 4.78M처럼 줄여요.
  - 돈은 `$26.21`, `₩63,718`처럼 쓰고, 좁은 곳에서는 `₩39만`처럼 줄여요.
  - '둘 다'를 고르면 좁은 칸에서는 원화를 작은 글씨로 둘째 줄에 둬요.
  - 남은 시간은 "3일 4시간", "2시간 13분", "45분", 짧게는 "↻02h"로 써요.

## 3. 구조

### 3.1 기술 스택

- **Rust + Tauri 2**(WebView2). 설치 파일은 약 2.3MB(NSIS)예요.
- UI는 **번들러 없는 순수 HTML/CSS/JS**예요. `ui/` 폴더가 그대로 `frontendDist`예요. 빌드 단계가 없어서 단순하고 빨라요.
- 쓰는 플러그인: notification, autostart, single-instance, opener, global-shortcut, updater.

### 3.2 폴더

```
crates/core/        순수 로직 (OS·Tauri 의존 없음) + 단위 테스트   ← 새 앱의 '기능'이 들어갈 곳
  src/settings.rs   설정 스키마·기본값·검증·마이그레이션
crates/devserver/   브라우저 미리보기 서버 (자동 새로고침)
src-tauri/src/
  lib.rs            앱 조립: 플러그인, 창, 트레이, 워커 스레드 시작
  state.rs          AppState(설정·캐시·Mutex), JSON 원자적 저장
  commands.rs       JS → Rust 명령 (창 조작, 설정 변경, 드래그 …)
  apply.rs          설정이 바뀌면 무엇을 다시 할지 (레이아웃, 단축키, 자동 실행 …)
  windows.rs        위젯·대시보드 창 생성/배치, z-order, 멀티 모니터
  workers.rs        백그라운드 스레드 (데이터 수집, 알림 판단, 창 유지)
  menu.rs, tray_icon.rs  트레이 메뉴와 트레이 아이콘(값을 그린 게이지)
  hotkeys.rs        전역 단축키 등록·녹음 중 해제
  updater.rs        자동 업데이트
  fx.rs, http.rs    외부 데이터 캐시 fetch 예시(환율), HTTP 공통
  setup.rs          '원클릭 연결' (터미널을 열어 설치·로그인 스크립트 실행)
ui/shared/          tokens.css, theme.js, util.js(포맷), render.js(위젯 렌더러), bridge.js, logos.js
ui/dashboard/       대시보드 페이지
ui/widget/          위젯 페이지
scripts/            mock-api.js(가짜 데이터 브리지), preview.js(스크린샷), make-icons.py
.github/workflows/  ci.yml(테스트), release.yml(서명된 릴리스)
```

### 3.3 JS ↔ Rust 브리지 패턴

- 모든 페이지는 `window.agentMeter` 하나만 써요 (`ui/shared/bridge.js`). 안에서 Tauri `invoke`/`listen`을 감싸요.
- 브라우저 미리보기에서는 `scripts/mock-api.js`가 같은 객체를 가짜 데이터로 제공해요.
  그래서 **UI 작업은 Tauri 없이 브라우저에서** 하고, Playwright로 스크린샷과 동작을 검증할 수 있어요.
- 데이터 흐름:
  - 시작할 때 `init()`으로 설정·스냅샷·버전 등을 한 번에 받아요.
  - 이후 변화는 이벤트(`usage`, `settings`, `event{type:…}`)로 밀어줘요.
  - 설정 변경은 `setSettings(patch)` 부분 패치로 보내요. Rust가 병합하고 검증한 다음 저장하고 모든 창에 다시 뿌려요.

### 3.4 설정 저장

- camelCase JSON 하나예요. 위치는 `%APPDATA%\<identifier>\settings.json`이에요.
- 저장은 원자적으로 해요: 임시 파일에 쓰고 rename해요. 직전 파일은 `.json.bak`으로 남겨서 깨졌을 때 백업에서 읽어요.
- `v` 필드로 버전을 관리해요. `from_value`에서 이전 버전이면 마이그레이션해요.
  - 예: v3에서 "Codex API 기본 켜기"를 기존 사용자에게도 적용했어요.
- `sanitize()`에서 모든 값의 범위를 강제해요. 너비 40~120, 색은 `#RRGGBB`만, 모르는 값은 기본값으로 바꿔요.
  UI에서 이상한 값이 와도 앱이 깨지지 않아요.

npm run dev            # 실제 앱 (tauri dev)

npm run screenshots    # README용 스크린샷

table.tbl { width: 100%; min-width: 300px; table-layout: fixed; }

## 5. 함정과 해결 (꼭 읽어 주세요)

### 5.1 창을 만드는 명령은 `async`로 만들어요 (Windows)
동기 `#[tauri::command]` 안에서 새 창을 만들면 WebView2가 교착되고 **흰 창만 떠요**.
창을 만들거나 닫는 명령(`open_dashboard`, `settings_set`, `close_window` …)은 전부 `pub async fn`으로 만들어요.

### 5.2 CSP: 페이지에 인라인 `<style>`을 넣지 마세요
인라인 `<style>`이 하나라도 있으면 Tauri가 CSP에 해시를 넣어요. 그러면 `'unsafe-inline'`이 무시돼서 **모든 `style="…"` 속성이 막혀요**.
그 결과 로고가 거대해지고 막대가 비는 일이 생겼어요. 스타일은 모두 외부 CSS 파일에 두고, `style=""` 속성(동적 너비 등)만 써요.

### 5.3 창 위치는 물리 픽셀로 다뤄요 (멀티 모니터)
- 위젯을 주 모니터 안으로만 제한했더니 모니터2로 옮길 때 튕겨 나왔어요.
  연결된 **모든 모니터**(`available_monitors`)를 기준으로, 잡을 수 있는 부분이 어느 화면에도 없을 때만 가장 가까운 모니터로 당겨요.
- 드래그는 JS의 `screenX`가 아니라 `window.cursor_position()`(물리 px)으로 계산해요.
  배율이 다른 모니터를 넘을 때 논리 px는 의미가 바뀌어서 튀어요.
- 저장 좌표는 "물리 px ÷ 주 모니터 배율" 하나로 통일해요 (`desktop_scale`).

### 5.4 항상 위 / 작업표시줄 위 (Windows)
- 다른 창이 앞으로 올 때마다 위젯이 깜빡였어요. `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`로 전경 창이 바뀔 때 `HWND_TOPMOST`로 다시 올리고, 40/120/300ms 뒤에 한 번씩 더 올려요.
- 같은 모니터에 전체 화면 창이 있으면 오히려 `HWND_NOTOPMOST`로 내려서 게임·영상을 가리지 않게 해요.
- 1초마다 도는 유지 스레드가 작업표시줄 크기 변화도 감지해요.
- 창이 파괴될 때 훅이 해제된 핸들을 만지지 않도록 먼저 정리해요 (`release_top`).

### 5.5 단축키 녹음은 모든 이탈 경로에서 취소해요
녹음하려고 전역 단축키를 해제했는데 녹음이 끝나지 않은 채 다른 곳으로 가면 단축키가 영영 죽어요.
Esc, 다른 탭 이동, 창 닫기, 숨김/최소화, **포커스만 잃은 경우(blur)** 모두에서 취소하고 재등록해야 해요.
네이티브 쪽에도 안전장치를 둬요: 대시보드 창이 파괴되면 해제된 상태였던 단축키를 되살려요.

### 5.6 알림 중복 방지
- "한 주기에 한 번"을 시각 값이 **같은지**로 판단하면 안 돼요. 서버가 매번 몇 초씩 다른 리셋 시각을 줘요. 1시간 안쪽이면 같은 주기로 봐요.
- 보낸 기록은 파일로 남겨요. 메모리에만 두면 재시작·자동 업데이트 때마다 다시 울려요.
- 임계치 알림은 히스테리시스를 둬요. 80%를 넘어서 울렸으면 70% 아래로 내려가야 다시 울릴 수 있어요.
- "예측" 알림은 정말 임박했을 때만 보내요(1시간 안). 그래도 많다고 느끼면 끌 수 있게 스위치를 둬요.

### 5.7 그 밖의 것
- **GTK(리눅스)는 처음 만든 크기보다 작게 창을 줄이지 못해요.** 위젯은 작게(120px) 만들고 페이지가 실제 크기를 알려주면 키워요.
- clippy는 테스트 모듈 뒤에 함수가 있으면 실패해요(`items_after_test_module`). 테스트는 파일 맨 끝에 둬요.
- JWT 만료(`exp`)를 읽으면 "로그인이 언제 만료되는지" 미리 보여줄 수 있어요.
- 외부 API를 너무 자주 부르면 429가 와요.
  - 평소 주기 + 활동이 있을 때만 앞당겨요(60초).
  - 429가 오면 간격을 2배로 늘려요(최대 4배).
  - 수동 새로고침은 15초에 한 번만 허용해요.
- 시간 표시는 데이터가 오래되면 "n분 전"을 흐리게(`stale`) 표시해서 사용자가 새로고침을 의심하지 않게 해요.

## 6. 배포와 자동 업데이트

1. **서명 키를 새로 만들어요.** 앱마다 따로 만들고, AgentMeter 키를 재사용하지 마세요.
   ```bash
   npx tauri signer generate -w ./myapp.key
   ```
   공개키는 `tauri.conf.json`의 `plugins.updater.pubkey`에 넣어요.
   **개인키는 저장소에 절대 커밋하지 말고** GitHub 저장소 Secrets의 `TAURI_SIGNING_PRIVATE_KEY`에만 넣어요.
   키를 잃어버리면 기존 설치본은 다시 자동 업데이트를 받을 수 없어요. 안전한 곳에 백업해 두세요.
2. `tauri.conf.json`의 `plugins.updater.endpoints`를
   `https://github.com/<owner>/<repo>/releases/latest/download/latest.json`으로 설정하고, Windows `installMode: "passive"`로 둬요.
3. `tauri.release.conf.json`:
   ```json
   { "bundle": { "targets": ["nsis"], "createUpdaterArtifacts": true } }
   ```
4. `.github/workflows/release.yml`을 복사하고 브랜치 이름만 바꿔요. 이 워크플로가 하는 일:
   - 푸시마다 버전을 `0.2.<실행번호>`로 올려요.
   - `tauri-action`으로 서명된 NSIS 설치 파일, `.sig`, `latest.json`을 만들어 GitHub 릴리스에 올려요.
   - 비밀키가 없으면 경고만 남기고 건너뛰어요.
   - 빌드할 때 `AGENTMETER_RELEASE=1`을 넘겨요. 이 값이 있는 빌드만 자동 업데이트·자동 실행 재등록을 해요.
     개발 빌드가 실수로 업데이트되지 않게 하려는 거예요. 새 앱에서는 이름을 바꿔도 돼요.
5. 앱 안 동작:
   - 시작 20초 뒤 첫 확인, 이후 3시간마다 확인해요.
   - 자동 업데이트가 켜져 있으면 받아서 설치하고 다시 시작해요. 꺼져 있으면 타이틀바 배지와 "설치하고 다시 시작" 버튼을 보여줘요.
   - 설치 직전에 설정과 캐시를 저장해요 (`on_before_exit`).
6. Authenticode 서명(코드 서명 인증서)이 없으면 처음 실행할 때 SmartScreen 경고가 떠요. 업데이트 서명과는 별개예요.
